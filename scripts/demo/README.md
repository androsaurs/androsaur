# demo.py: запись демо-роликов с телефона

Снимает экран телефона, пока приложение проигрывает сценарий, и собирает ролики EN/RU с субтитрами. Полное описание шагов сцены и ограничений: `docs/demo-recording.md`.

## Подготовка (один раз)

1. `cd scripts/demo && npm install` — ставит `ffmpeg` (лежит в `node_modules`, в git не идёт).
2. Телефон подключён по adb (`adb devices`), на нём стоит свежий `androsaur` с приёмником `DEBUG_SCENE`
   (сборка: `ANDROID_HOME=~/Android/Sdk ./gradlew :androidApp:assembleDebug`, установка: `adb install -r androidApp/build/outputs/apk/debug/androidApp-debug.apk`).
3. Если телефонов несколько: `--device <serial>` или `DEMO_DEVICE=<serial>`.

## Команды

```bash
python3 demo.py all     scenarios/launch.json            # снять и собрать
python3 demo.py record  scenarios/launch.json            # только съёмка → raw/launch.mp4
python3 demo.py compose scenarios/launch.json            # только сборка из raw → out/
python3 demo.py frames  out/launch-wide-ru.mp4 5 20 30   # кадры PNG в out/frames/ для проверки глазами
```

Результат `out/<сценарий>-{wide,tall}-{en,ru}.mp4`: `wide` 1920×1080 (телефон слева, текст справа), `tall` 1080×1920 (шортс по шаблону компоновки, см. ниже). H.264, 30 кадров/с, без звука.

Собрать одну версию (быстрее и дешевле по памяти): `python3 demo.py compose scenarios/launch.json --lang ru --kind tall`.

## Как пройдёт съёмка

1. Открывается приложение, выполняются шаги `setup`, пауза `settle` секунд: первый кадр уже «в сцене».
2. Запускается `screenrecord` и действия сцен (`do`) подаются по таймлайну (секунды от начала записи, запас 0,6 с на старт записи).
3. По окончании `reset` возвращает приложение к реальной камере, ролик скачивается в `raw/` и удаляется с телефона.

Во время съёмки не трогайте телефон и не стойте в кадре камеры: сцена изолирует реальную камеру, но экран пишется как есть (уведомления попадут в ролик).

## Шаблон вертикального шортса (`layouts/tall-a.json`)

Вид шортса задаётся шаблоном, а не кодом. Вариант A утверждён 07.11.2026; эталон вида: `layouts/tall-a.png` (кадр из готового ролика). Сверху плашка проекта и заголовок сцены, потом прямой телефон в толстой серой рамке на тёмном фоне с зелёным свечением, снизу карточка с подписью.

| Что | Ключ в JSON | Значение (кадр 1080×1920) |
|---|---|---|
| Телефон: высота корпуса, верх, толщина рамки | `phone.body_height`, `top`, `bezel` | 1300, 310, 16 |
| Плашка проекта (верх, размер шрифта) | `chip.y`, `chip.size` | 110, 30 |
| Заголовок сцены (верх, размер) | `title.y`, `title.size` | 205, 66 |
| Карточка подписи (верх, размер, ширина текста, подпись-отправитель) | `card.y`, `card.size`, `card.max_text_width`, `card.label_size` | 1655, 54, 860, 28 |
| Свечение фона (центр по вертикали, радиусы) | `background.glow_center_y`, `glow_rx`, `glow_ry` | 800, 560, 620 |
| Цвета | `background`, `chip`, `title`, `card` | см. файл |

Новый шаблон: скопируйте `layouts/tall-a.json` в `layouts/<имя>.json`, поправьте значения и укажите `"layout": "<имя>"` в сценарии (по умолчанию `tall-a`). Менять размеры в `demo.py` не нужно. Что держать в голове при правке:
- карточка с тремя строками подписи кончается около 1900 из 1920, поэтому `card.y` выше 1660 уже не лезет;
- YouTube Shorts частично закрывает нижние 25% кадра (ниже 1440) своими кнопками: карточка в этой зоне, это цена крупного телефона;
- после правки шаблона соберите один ролик и сравните кадр с `layouts/tall-a.png`.

## Новый ролик

1. Скопируйте `scenarios/launch.json` в `scenarios/<имя>.json`.
2. Поправьте `duration` (запись обрывается через `duration + 2` с, предел screenrecord 180 с) и `chip` (`{en, ru}`: текст плашки проекта); при желании задайте `layout`.
3. Опишите сцены в `scenes`. Сцена — один элемент, в нём всё, что относится к ней:
   - `from`, `to` (секунды от начала записи): когда показывается подпись;
   - `title` (`{en, ru}`): заголовок сцены цветной строкой в карточке, до 22 знаков;
   - `en`, `ru`: текст карточки, до трёх строк;
   - `label` (`{en, ru}`), необязательно: отправитель, префикс текста («Вы: …», «Зюзя: …»). Реплики говорящих подписывайте, пояснения оставляйте без подписи;
   - `do`, необязательно: действия на телефоне `{dt, step, ...}`; `dt` в секундах от начала сцены, может быть отрицательным (действие чуть раньше подписи). Команды: `profile`, `face_in`, `face_out`, `wake`, `command`, `say`, `note`, `sleep`, `reset`. Перед началом записи выполняются `setup` и пауза `settle`.

   Пример сцены: `{"from": 22.2, "to": 29.5, "title": {...}, "label": {...}, "en": "...", "ru": "...", "do": [{"dt": -0.2, "step": "command", "intent": "character_glasses", "data": "wear=true;personId=demo"}]}`.
4. `python3 demo.py all scenarios/<имя>.json`, затем `frames` на ключевых секундах и просмотр глазами.

## Если что-то не так

- **Первый кадр пустой или видна системная панель:** приложение только что установлено или было закрыто. Запустите его вручную, подождите 5–10 с и снимите заново.
- **На экране «Не узнаю» или чужой персонаж:** сцена не началась. Проверьте, что установлена свежая сборка, и что `setup` содержит `profile`.
- **`нет телефона по adb`:** `adb connect <ip>:<порт>` или USB.
- **`нет ffmpeg`:** выполните `npm install` в `scripts/demo`.
- **Субтитры не помещаются:** в вертикальном ролике сократите текст карточки (до трёх строк) или поправьте `card.size` в шаблоне; в горизонтальном кегль задаётся константой `54` в функции `ass` файла `demo.py`.
- **Сборка съела память:** вертикальный ролик собирается потоком (ffmpeg декодирует и кодирует, наложение делает Python по кадру), замер: 35 с, пик 0,7 ГБ. Не возвращайтесь к графу ffmpeg с зацикленными картинками (`-loop 1`): такой граф съел 16 ГБ. Тяжёлые сборки запускайте с `ulimit -v 6000000`.
