# Два режима персонажа

## Личные персонажи и каталог (05.11.2026)

Встроены пять Rive-ригов: зелёный `dinosaur`, сиреневая кошечка `cat` с
треугольными розовыми ушами и усами, рыжая собачка `dog` с висячими ушами и пятном,
пушистый сиреневый `puf` (Пуф) с хохолками и золотистый `hamster` (Хомяк) со
щёчками, усами, круглыми ушами и передними зубками из переданных владельцем патчей.
Все используют одинаковый контракт состояния, речь, взгляд, сон и выражения.

В хабе `/characters` ребёнок сначала смотрит анимированные SVG-предпросмотры,
выбирает своё имя и персонажа. SVG получены из тех же фигур генератора: они
показывают внешность, дыхание и моргание, кнопка добавляет приветственное движение.
Это лёгкий предпросмотр в браузере; на телефоне анимацией управляет Rive.
Ссылка «Каталог · выбрать для себя» есть в панели приложения.

Пуф доступен с `0.4.3-puf`, выбранный ID — `puf`. Он подключён как личный персонаж
в сложном режиме, отдельного третьего режима рендера нет. У него artboard «Пуф»,
у динозавра, кошечки и собачки — `Androsaur`; машина у всех `Character`. Помимо семи общих числовых
входов у Пуфа есть `outfit` (0 без украшений, 1 шарфик, 2 венок, 3 очки, 4 бантик).
В каталоге базовый предпросмотр Пуфа; аксессуары управляются голосом (см. ниже).
Лоадер проверяет точный набор входов для каждого рига.
При добавлении бинарный `puf_character.riv` совпадал с исходником из патча;
с 0.5.1 линзы очков затемнены по просьбе владельца. Генератор вынесен в
`scripts/build-puf-rig.mjs`, его writer — `scripts/rive/writer.mjs`.

```sh
node scripts/build-puf-rig.mjs androidApp/src/main/res/raw/puf_character.riv --preview=../androsaur-hub/app/static/characters/puf.svg
```

SVG строится из тех же компонентов, трансформаций, цветов и прозрачности; анимация
предпросмотра облегчённая, на телефоне используется оригинальная машина Rive.

Хомяк доступен с `0.4.4-hamster`, ID — `hamster`, artboard «Хомяк». Его бинарный
файл при добавлении также точно совпадал с патчем; с 0.5.1 очки стали солнечными.
Контракт включает `outfit`: 0 без украшений,
1 семечка в лапках, 2 бантик, 3 очки. В каталоге базовый вариант; отдельного режима
рендера нет. Аксессуары управляются голосом. Встроены дыхание, моргание, движения носа,
усов и ушей, щёчки меняются при внимании, рот с языком и зубками открывается при речи.

```sh
node scripts/build-hamster-rig.mjs androidApp/src/main/res/raw/hamster_character.riv --preview=../androsaur-hub/app/static/characters/hamster.svg
```

Пингвин — `penguin`, artboard «Пингвин», синий пингвинёнок с большой головой, оранжевыми лапками, светлой
обводкой и мягким свечением, чтобы читаться на чёрном экране. Бинарный `penguin_character.riv` при добавлении
совпал с исходником из патча (версия с треугольным клювом и перепончатыми лапами: в writer добавлен `outline` — замкнутый контур по точкам с закруглением углов). Контракт включает `outfit`: 0 без одежды, 1 шапка с помпоном, 2 наушники,
3 шарф, 4 кепка, 5 толстовка. Все пять доступны голосом (см. таблицу ниже); хранимые ID — `bobble_hat`,
`headphones`, `scarf`, `cap`, `hoodie`. Writer получил градиент, обводку и обрезку по контуру (`clip`), `svg()` их рисует.

```sh
node scripts/build-penguin-rig.mjs androidApp/src/main/res/raw/penguin_character.riv --preview=../androsaur-hub/app/static/characters/penguin.svg
```

Пингвин 2 — `penguin2`, второй вариант пингвина (выбирали между двумя, оставлены оба). Тот же artboard «Пингвин»,
файл `penguin2_character.riv`, тот же контракт, `outfit` и наряды с теми же ID и командами, что у пингвина.
Отличие в рисунке: настоящая анатомия — одно грушевидное тело без шеи, высокое яйцевидное белое брюшко, ласты-треугольники,
клин-клюв и небольшие перепончатые лапы. Тело строится из гладких вершин (`{x, y, angle, dist}` в `outline`), поэтому
риг создаётся с `reversePoints: true`: writer добавляет точки в обратном порядке, и Rive проходит их в заданном
порядке. Бинарный файл совпал с исходником из патча. Предпросмотр `svg()` понимает гладкие вершины и обрезку
по фигуре из любой ветки дерева.

```sh
node scripts/build-penguin2-rig.mjs androidApp/src/main/res/raw/penguin2_character.riv --preview=../androsaur-hub/app/static/characters/penguin2.svg
```

### Все аксессуары (0.6-character-accessories)

Голосовое управление всеми нарисованными аксессуарами требует главного приложения
0.6 и аудиомодуля 0.4-character-accessories. После пробуждения доступны:

| Команда | Пуф | Хомяк | Сохраняемый ID |
| --- | --- | --- | --- |
| «Надень бантик» / «надень бант» | outfit 4 | outfit 2 | bow |
| «Надень шарфик» / «надень шарф» | outfit 1 | нет | scarf (пингвин, outfit 3) |
| «Надень венок» | outfit 2 | нет | crown |
| «Возьми семечку» / «дай семечку» | нет | outfit 1 | seed |
| «Надень очки» | outfit 3 | outfit 3 | glasses |
| «Надень шапку» / «шапочку» / «колпак» | нет | нет | bobble_hat (пингвин, outfit 1) |
| «Надень наушники» | нет | нет | headphones (пингвин, outfit 2) |
| «Надень кепку» | нет | нет | cap (пингвин, outfit 4) |
| «Надень толстовку» / «худи» | нет | нет | hoodie (пингвин, outfit 5) |
| «Сними всё» / «сними все аксессуары» | outfit 0 | outfit 0 | none |

Снятие конкретного предмета: «сними бантик», «сними шарф», «сними венок»,
«убери семечку» / «отложи семечку», «сними очки». Снимается только названный
надетый предмет: «сними бант» не убирает очки. Новый предмет заменяет предыдущий,
одновременно доступен один. Отрицания, содержимое записки и неоднозначные
«надень очки и бант» не выполняются как команда переодевания.
«Повяжи» нет в словаре Vosk: для голосового вызова используйте «надень шарфик».
Неподдерживаемый предмет вызывает голосовое объяснение без изменения профиля.

В хаб и кэш передаются смысловые ID, а номера outfit выбираются на телефоне по
персонажу. Поэтому разные коды бантика не смешиваются. Очередь, защита от старых
подтверждений и работа без хаба общие для всех аксессуаров. Миграция ограничения
CHECK в `character_accessories` расширяет список ID транзакционно, сохраняя
старые очки; регрессионный тест проверяет обновление старой БД и повторный старт.
`CharacterOtherAccessoriesRenderingTest` по native-пикселям проверяет оба бантика,
шарф, венок и семечку, включая их снятие.

### Голосовые очки (добавлены в 0.5-character-glasses)

После «Зюзя» — «надень очки» / «одень очки» и «сними очки» / «убери очки».
Команды распознаёт аудиомодуль 0.3-character-glasses через тот же Vosk после
пробуждения, без LLM. Все слова есть в словаре модели. Отрицания и фразы внутри
записки вроде «передай маме надень очки» не считаются командой аксессуара.
Событие `command` несёт `intent=character_glasses`, `wear=true|false` и текущий
`personId` контекста. Главное приложение проверяет, что перед камерой узнанный
человек, и отвечает голосом. Если человек сменился или персонаж не поддерживает
очки, чужой профиль не меняется. У динозавра, кошечки и собачки очков пока нет.

Выбор `none` / `glasses` хранится по паре person ID + character ID: очки Пуфа и
Хомяка независимы. Для обоих `glasses` соответствует `outfit=3`, снятие — 0.
Один аксессуар за раз: очки заменяют другие украшения. В простом режиме выбор
сохраняется, а ассистент объясняет, что виден он будет в сложном режиме.

С `0.5.1-sunglasses` это тёмные солнечные очки на обоих персонажах: непрозрачные
линзы `#11151e` закрывают глаза, сверху небольшие приглушённые блики. Команды,
ID аксессуара и outfit=3 не менялись, сохранённый выбор продолжает работать.
Native-тест проверяет не только оправу, но и наличие тёмных пикселей линз при
надевании и их полное исчезновение при снятии.

Кэш `brain.person_accessories` и очередь `brain.pending_accessories` сохраняются
одним обновлением SharedPreferences. Команда меняет местный вид сразу, без хаба.
Фоновый обмен отправляет очередь даже после ухода человека; сетевые ошибки
оставляют её на диске. Обновления из хаба не стирают неотправленные команды;
старое подтверждение не удаляет более новую команду для той же пары.

Хаб хранит `character_accessories`, отдаёт `accessories: {personId: {characterId:
accessory}}` в sync и GET /api/characters. POST /api/characters/accessory принимает
`{person, character, accessory}` и возвращает полный внешний вид; теперь доступны
none/glasses/bow/scarf/crown/seed в пределах возможностей персонажа. Запись атомарно
проверяет, что человек активен и по-прежнему выбрал именно этого персонажа.
409 отклоняет устаревшее изменение после смены персонажа; неизвестный человек,
сеть и 5xx оставляют очередь для повторной попытки. Старый хаб без нового API
не мешает местному управлению очками.

Тесты проверяют офлайн-очередь после восстановления, порядок подтверждений,
независимость людей/персонажей, доставку через хаб, переименование и конфликты.
`CharacterGlassesRenderingTest` по пикселям настоящих native-текстур проверяет
появление и снятие очков на обоих персонажах.

Выбор привязан к постоянному ID человека, а не к телефону и не к имени. Хаб
отдаёт полный словарь `characters: {personId: characterId}` в register/sync;
каждый телефон сохраняет его в `brain.person_characters`. Отсутствие поля у
старого хаба сохраняет кэш, пустой словарь очищает выбор. Незнакомый ID персонажа
даёт динозавра. Риги встроены в APK, поэтому последнее соответствие и персонажи
работают без хаба и интернета после перезапуска. Новые риги в этой версии требуют
обновления APK; удалённая загрузка произвольных ригов не реализована.

С версии `0.4.1-character-refresh` телефон дополнительно читает `GET /api/characters`
в начале узнавания и при получении личности. Пока камера видит человека, короткий
запрос повторяется каждые 2 с. Он выполняется в отдельной корутине и не задерживает
камеру или отрисовку; connect/read timeout 1000/1200 мс. HTTP-кэш отключён на обеих
сторонах. При недоступном хабе остаётся сохранённый выбор. Ответы применяются по
порядку начала запросов: запоздавший старый общий sync не может отменить уже
полученный более свежий выбор. Сетевые ошибки не очищают сохранённые соответствия.

В сложном режиме персонаж выбирается по ID человека, которого узнаёт камера.
При узнавании другого человека выбор меняется сразу с переходом 350 мс.
При краткой потере лица/неудачном узнавании предыдущий персонаж остаётся до 8 с
после последнего присутствия с известным ID; затем возвращается динозаврик.
Учитывается существующий допуск присутствия камеры. Смена имени не меняет выбор.
При нескольких лицах используется текущий результат узнавания камеры; отдельного
арбитража между собеседниками пока нет. Простой режим остаётся самостоятельным
ручным выбором и показывает глаза/рот независимо от личного персонажа.

Пересборка ригов и SVG (из корня `androsaur`, каталоги репозиториев соседние):

```sh
node scripts/build-character-rig.mjs androidApp/src/main/res/raw/androsaur_character.riv dinosaur ../androsaur-hub/app/static/characters/dinosaur.svg
node scripts/build-character-rig.mjs androidApp/src/main/res/raw/androsaur_cat.riv cat ../androsaur-hub/app/static/characters/cat.svg
node scripts/build-character-rig.mjs androidApp/src/main/res/raw/androsaur_dog.riv dog ../androsaur-hub/app/static/characters/dog.svg
```

Нативный тест `CharacterRigTest` загружает все пять файлов и прогоняет весь контракт,
включая числовые входы аксессуаров Пуфа и Хомяка.
`PersonalCharacterTest` проверяет выбор по ID, смену человека, паузу до возврата,
обновление/очистку соответствий и неизвестные риги. Хаб проверяет доставку на
несколько устройств, повторную инициализацию БД, переименование, объединение людей
и отклонение недопустимого выбора без потери предыдущего.

В панели приложения (касание лица) раздел «Персонаж» переключает «Простой» и
«Сложный». По умолчанию используется простой режим. Выбор хранится в настройках
телефона `brain.character_mode`, переживает перезапуск и работает без хаба.

Простой режим — прежние глаза и рот на Compose Canvas. Сложный — собственный
пробный динозавр Rive: дыхание, моргание, взгляд, раскрытие рта, выражения и
движение рук при слушании/речи. Это демонстрационный персонаж, его внешность
не является утверждённым дизайном продукта. Риг построен из векторных фигур
и иерархии узлов; skinning и mesh-деформации в этом прототипе не используются.

## Общий слой

`shared/.../character/CharacterState.kt` — состояние без Android и Rive.
`Brain.character` публикует его через `StateFlow` каждые 50 мс только при
изменениях значения; сбор данных работает вместе с остальными задачами Brain,
пока Activity находится в STARTED. Дополнительных сетевых запросов для персонажа
нет. UI подписывается через `collectAsStateWithLifecycle`.

Состояние содержит выражение, экранные координаты взгляда -1..1, признак речи,
раскрытие рта 0..1, взаимодействие (`IDLE`, `COMMAND`, `RECORDING`, `NOTE`) и
затемнение. Ожидание команды и запись сохраняют выражение LISTENING после
трёхсекундной реакции на wake-word. При отсутствии речи рот закрывается;
некорректные числовые значения ограничиваются перед передачей renderer.

`CharacterView` выбирает renderer и применяет общее смещение от выгорания.
`SimpleFace` и `RiveCharacter` получают только состояние. Часы, погода, таймер,
имя человека и текстовые подсказки рисуются отдельно от персонажа.

## Rive

Используется `app.rive:rive-android:10.0.5` (MIT), совместимый с текущим Kotlin
и Android SDK проекта. Выбран renderer Canvas; нативная библиотека загружается
лениво при первом включении сложного режима. Проверенная здесь версия закреплена
явно, обновлять её следует вместе с проверкой рига и жизненного цикла.
Версия 10.4.0 подтягивает Lifecycle 2.9.1, чей lint-detector несовместим с UAST
текущего AGP 8.7.3. Поэтому выбран runtime 10.0.5 с Lifecycle 2.8.7,
без отключения проверок lint или обновления всей сборочной цепочки.

Файл: `androidApp/src/main/res/raw/androsaur_character.riv`.
Artboard: `Androsaur`. State machine: `Character`.
Все входы числовые:

| Вход | Значения |
| --- | --- |
| `lookX` | -1..1, вправо по экрану положительное |
| `lookY` | -1..1, вниз по экрану положительное |
| `mouthOpen` | 0..1, раскрытие по громкости воспроизводимого звука |
| `expression` | 0 NEUTRAL, 1 ATTENTIVE, 2 LISTENING, 3 SLEEPY, 4 SAD, 5 TIRED, 6 EXHAUSTED |
| `interaction` | 0 IDLE, 1 COMMAND, 2 RECORDING, 3 NOTE |
| `speaking` | 0/1 |
| `sleeping` | 0/1; останавливает автономные движения |

Положение взгляда и рот сглаживаются в адаптере; дыхание и моргание
выполняются внутри `.riv`. Код выражения передаётся сразу: это категория, а не
непрерывная шкала. В каждом риге выражения — отдельные AnimationState (персонажей семь: динозавр, кошка и собака собираются одним скриптом, пуф, хомяк и два пингвина — своими);
переход из Any выбирает нужную позу по равенству кода и смешивает исходную и
конечную позы за 300 мс. Новый код может прервать ещё незавершённый переход.
Так NEUTRAL → SAD не проходит через ATTENTIVE/LISTENING/SLEEPY и не прикрывает
глаза как при сонливости. Исправлено в `0.4.2-expression-states`.
### Улыбка у динозавра, кошки и собаки (2026-11-07)

В обычной позе у них лёгкая улыбка, как у Пуфа и хомяка: тёмный овал рта (`Mouth hole`) с «крышкой» цвета мордочки
(`Mouth lid`) сверху даёт тонкий полумесяц. При речи крышка исчезает (прозрачность 1 → 0) и овал раскрывается по громкости,
у грустных поз узел `Mouth` переворачивается по Y (отрицательный масштаб), и улыбка становится дугой вниз. Узел рта общий
для поз (`scaleX`, `scaleY` в позах 0–6), раскрытие рта и прозрачность крышки задаёт слой `mouthOpen`.

### «Уставший» и «валится с ног» (2026-11-07)

Коды 5 и 6 показываются после первого и после финального напоминания не засиживаться (`health/Sitting.kt`): персонаж
грустный и уставший (тяжёлые веки, брови домиком, голова чуть клонится, корпус слегка оседает), затем валится с ног
(глаза сощурены, корпус оседает и кренится, голова падает набок, руки обвисают); после перерыва сразу обычный.
У скрипта динозавра/кошки/собаки (`scripts/build-character-rig.mjs`) для этого добавлены узлы-обёртки `Figure`, `Head droop`,
`Left/Right arm hang`: они не заняты другими слоями (взгляд, дыхание, речь), поэтому поза не спорит с ними. Каждая поза
выражения задаёт все свои свойства, иначе после ухода из неё остались бы значения предыдущей. Те же две позы есть у всех семи персонажей: у Пуфа, хомяка и двух пингвинов
их скрипты получили такие же узлы-обёртки (`Figure`, `Head droop` или поза головы/лица, `… arm/flipper hang`), корпус пингвинов
наклоняется от бёдер, а ноги и лапы остаются на земле.

Посмотреть позу без человека: `adb shell am broadcast -a dev.hram.androsaur.DEBUG_FACE -p dev.hram.androsaur --es character dinosaur
--es expression exhausted --ei seconds 25`, затем `adb exec-out screencap -p > pose.png` (выражение: neutral, attentive, listening,
sleepy, sad, tired, exhausted; персонаж: dinosaur, cat, dog, puf, hamster, penguin, penguin2). Приёмник защищён системным
разрешением DUMP и только временно подменяет лицо.

Риг проверяется на наличие artboard, state machine
и полный набор числовых входов до начала воспроизведения. Ошибка загрузки
или передачи входов включает простое лицо и сообщение в панели. Это обработка
ошибок Kotlin/JNI; аварийное завершение внутри нативного кода ей не перехватить.

При сне renderer приостанавливается после перехода в неподвижную позу.
Повтор одинаковых входов не будит его при каждом обновлении часов.
При уходе Activity в фон воспроизведение и продвижение контроллера выключаются,
при возврате персонаж возобновляется, даже если он был сонным. Смена режима освобождает файл
и artboard, а Rive освобождает renderer при отсоединении Android View.
В `CharacterRiveView.onSurfaceTextureSizeChanged` обновляются границы
контроллера и запрашивается отрисовка без пересоздания Surface.
Стандартный callback Rive пересоздаёт Surface и может освободить её
до окончания `unlockCanvasAndPost` в потоке рисования: это воспроизвелось на
Redmi 12 / Android 15 при запуске с изменением размеров лица. Обход сохраняет
существующую поверхность TextureView.

В `0.8.1-sleep-render` исправлено исчезновение сонного персонажа при живых
часах/погоде. Раньше сон ставил controller.isActive=false после pause(),
поэтому очередной кадр очищал Surface, но Rive draw() пропускал artboard.
Теперь во сне ставится pause() (останавливает движение/цикл кадров), а
controller остаётся активным для статической перерисовки. Новая поверхность
или изменение размера получают кадр и во сне. При возврате Activity сначала
включается отрисовка, затем через450мс снова приостанавливается сонная поза.
В фоне и при освобождении controller по-прежнему выключается.

Добавлен Android-тест повторной отрисовки/изменения размера во сне с проверкой
пикселей. MIUI на Redmi12 отказала в установке отдельного testAPK; сборка теста
проходит, но его выполнение на этом телефоне не подтверждено.

## Исходник пробного рига

Авторский исходник — `scripts/build-character-rig.mjs`. Скрипт не требует
внешних пакетов и записывает небольшой runtime-файл Rive v7 из фигур, ключевых
кадров и слоёв смешивания. Численные идентификаторы объектов и полей взяты
из публичного формата `rive-app/rive-runtime`; стороннего рисунка нет.
Код генератора и персонаж распространяются на условиях лицензии проекта.
Системные состояния Any, Entry и Exit сохранены для старых runtime.
Порядок компонентов в файле обратный порядку рисования; генератор пересчитывает
ссылки на родителей и цели анимаций при перестановке.

Перегенерация из корня репозитория:

```sh
node scripts/build-character-rig.mjs
```

Для другого персонажа можно создать риг в редакторе Rive и заменить `.riv`,
сохранив контракт, либо написать отдельный адаптер его входов к `CharacterState`.
Сборка Android использует уже включённый файл, Node для неё не нужен.
Амплитудная анимация рта не является артикуляцией по фонемам.

## Проверки

```sh
./gradlew :androidApp:assembleDebug :shared:jvmTest :androidApp:lintDebug
./gradlew :androidApp:connectedDebugAndroidTest
```

Общие тесты проверяют слушание, сон, нормализацию сигналов и восстановление
режима. Android-тесты загружают настоящий bundled rig нативным runtime,
прогоняют выражения с речью и взглядом, проверяют переключение, пересоздание
Activity и возврат к простому лицу при отказе загрузчика.
Тест отрисовки проверяет пиксели настоящей нативной текстуры: видимость глаз,
увеличение рта при речи, остановку state machine во сне и возобновление.
Производительность, нагрев и синхронизацию с реальным звуковым модулем следует
измерить на целевых телефонах.

Регрессионный `CharacterExpressionTest` проверяет в настоящем native runtime
все 20 направленных переходов между разными эмоциями для каждого из пяти ригов,
отсутствие промежуточных выражений, а также прерывание смешивания новой эмоцией.
`CharacterRenderingTest` дополнительно замораживает часы Compose и проверяет,
что новый категориальный код всё равно сразу поступает в Rive: числовой tween
в адаптере не должен возвращаться.
Для Пуфа и Хомяка отдельные проверки native-текстуры подтверждают видимые глаза и
увеличение открытого рта при речи; тест смены личных персонажей включает обоих.
